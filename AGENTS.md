# Bahts — mesin penulisan bahts (riset ilmiah berbahasa Arab)

Satu bahts = satu folder; yang ditulis cuma `naskah.txt`, sisanya (cek rujukan, Word, PDF) dikerjakan mesin. Bahan bahts jangan masuk `mesin/`; `kitab/` dipakai semua bahts.
Daftar perintah: `python mesin/bahts.py`. Daftar tanda naskah: `python mesin/bahts.py tanda`.

## Pemakai baru

Anggap pemakai baru pertama kali memakai agent, tidak membaca README, dan hanya memberi tautan repo plus permintaan bahts. Kerjakan semuanya sendiri; pemakai cukup menjawab pertanyaan. Pakai bahasa awam.

1. Repo belum ada di komputer → cek dulu folder `mesin-bahts` di dalam folder Dokumen pemakai. Belum ada → unduh ke sana: `git clone`, atau kalau `git` tidak ada, unduh `https://github.com/Farisarditiyanto/mesin-bahts/archive/refs/heads/main.zip` lalu ekstrak dan namai foldernya `mesin-bahts` (zip itu terekstrak sebagai `mesin-bahts-main`). Folder Dokumen = folder dokumen akun pemakai (di Windows bisa berada di dalam OneDrive). Jangan mengunduh ke folder sistem, folder program, atau folder kerja orang lain. Semua bahts pemakai tinggal di dalam folder itu.
2. Jalankan `python mesin/bahts.py periksa` (di Linux/macOS biasanya `python3`). Bereskan sendiri tiap baris `BELUM` dengan perintah yang disebutnya, lalu ulangi sampai tidak ada lagi yang bisa kamu bereskan. Baris huruf bertulisan «(hanya untuk @format …)» dilewati, kecuali naskah memakai profil itu: baris itu tidak menahan `rakit`, dan perintahnya memunculkan jendela izin admin. `python` tidak dikenal → pasang Python 3.12 dulu (Windows: `winget install Python.Python.3.12`); kalau sesudah itu `python` masih tidak dikenal di terminalmu, pakai `py`. Beri tahu pemakai bahwa `siapkan` memasang satu font (font mushaf) untuk akunnya.
3. `periksa` bilang `rakit` BELUM karena Windows atau Microsoft Word → beri tahu pemakai SEKARANG, sebelum menulis apa pun: hasilnya berhenti di naskah yang sudah dicek, tanpa Word dan PDF. Tanya: lanjut, atau pasang Word dulu. Jangan memasang Word sendiri dan jangan memakai pengganti Word. Yang BELUM «huruf Traditional Arabic» → jalankan perintah PowerShell admin yang disebut `periksa`, dan beri tahu pemakai dulu bahwa Windows akan menampilkan satu jendela izin: cukup klik Yes. Perintah itu selesai sesudah jendelanya menutup; ulangi `periksa`. Masih BELUM → minta pemakai menambah papan ketik Arab seperti yang disebut `periksa`.
4. Connector `shamela` wajib: jangan mengumpulkan bahan sebelum alat `shamela_*` tersedia. Sebelum menyimpulkan alatnya tidak ada, cari dulu dengan pencari alat agentmu (Claude Code: ToolSearch «shamela»): di banyak agent alat connector disembunyikan sampai dicari, dan lewat gateway MCP namanya berawalan lain (mis. `toolport__shamela__shamela_search_phrase`), barangnya sama. Tanda `shamela` tersambung = ada `shamela_search_phrase`. Alat `shamela_*` tetap tidak ada → beri tahu pemakai: connector ini wajib, gunanya (mencari kitab yang membahas suatu masalah, termasuk yang belum diunduh) dan caranya: masuk dengan akun shamela.link sendiri sesudah connector-nya dinyalakan. Daftar connector dibaca sendiri oleh Claude Code dan Command Code (dari `.mcp.json`) serta OpenCode (dari `opencode.json`). Masuk akunnya: Claude Code `/mcp`; OpenCode `opencode mcp auth shamela`. Command Code: pendaftaran login otomatisnya ditolak shamela.link, jadi entri `shamela` di `.mcp.json` ditimpa entri lokal (di `~/.commandcode`, di luar repo: tanya pemakai dulu) yang membawa `clientId` repo. Beri tahu pemakai bahwa browser akan terbuka untuk masuk shamela.link. Dari folder repo, lewat bash atau PowerShell 7 (`pwsh`; PowerShell 5.1 membuang tanda kutip di dalam JSON), jalankan `commandcode mcp add-json --scope local shamela '{"type":"http","url":"https://shamela.link/mcp","oauth":{"clientId":"XibdiamYnAOtrCxycxRltQsDFisFhAWc","authorizationUrl":"https://shamela.link/api/auth/oauth2/authorize","tokenUrl":"https://shamela.link/api/auth/oauth2/token","scopes":["openid","offline_access"],"resource":"https://shamela.link/mcp","callbackPort":8085}}'` (di Git Bash, `cmd` = `cmd.exe` Windows: pakai `commandcode`). Perintah itu membuka login kalau belum ada token. `commandcode mcp list` harus menulis `shamela … local ✔`; belum ✔ → `commandcode mcp auth shamela`. Sesudah itu mulai sesi baru. Agent lain tidak membaca kedua berkas itu: daftarkan alamat dari `.mcp.json` lewat pengaturan MCP agent tersebut (Codex: `codex mcp add shamela --url https://shamela.link/mcp`, lalu `codex mcp login shamela`; Hermes: `hermes mcp add shamela --url https://shamela.link/mcp --auth oauth`, tautan masuknya muncul saat pertama tersambung). Connector tanpa akun didaftarkan dengan cara yang sama, tanpa langkah masuk. Itu mengubah pengaturan agent pemakai di luar repo: tanya dulu. Pemakai menolak atau belum bisa masuk → jangan mulai mengumpulkan bahan; jelaskan sebabnya dan tunggu sampai `shamela` tersambung.
5. Connector tanpa akun di `.mcp.json` ikut dipasang bersama `shamela`, supaya semuanya siap walau tidak semua dipakai: `turath` (isi semua kitab), `hadithunlocked` (hadits, derajat, syarah, sejarah), `tafsir` (tafsir per ayat, sebab turun, qiraat, i'rab), `quran` (teks ayat, morfologi, sebaran kata). Semuanya penunjuk jalan. Minta izinnya sekali untuk semua connector, jangan satu per satu. Bedanya dengan `shamela`: yang ini tidak menahan pekerjaan. Layanannya mati atau gagal tersambung → lanjut, lalu sebut di laporan akhir. Pemakai menolak → lewati.
6. Kunci OpenAlex wajib hanya untuk bahts yang memuat الدراسات السابقة; bahts lain tidak memerlukannya, jadi jangan dimintakan di awal. Dosen minta الدراسات السابقة, `kunci_openalex.txt` belum ada, dan variabel lingkungan `OPENALEX_API_KEY` kosong → minta kunci gratis (openalex.org > Settings > API key) sebelum menulis `#S`: tanpa kunci `dirasat-pdf` tertutup, jadi isi penelitiannya tidak bisa dibaca. Pemakai memberi kuncinya → simpan sebagai satu baris di berkas itu. Jangan menulis kunci itu di tempat lain.

## Sebelum tiap bahts

- Perbarui mesin hanya sebelum mulai bahts baru, jangan saat bahts sedang dikerjakan: `cek` versi baru bisa menggagalkan naskah yang tadinya lolos.
  1. Folder ini repo git dan `git status --porcelain` kosong → jalankan `git pull --ff-only`, lalu ulangi `periksa`.
  2. Perintah itu gagal atau ada perubahan lokal → jangan dipaksa. Beri tahu pemakai, lalu lanjut dengan versi yang ada.
  3. Bukan repo git (dulu diunduh sebagai zip) → beri tahu pemakai bahwa versi baru tidak diambil otomatis. Jangan menimpa folder ini: semua bahtsnya ada di dalam.
- `sampul_saya.txt` belum ada → tanya pemakai sekali: nama (huruf Arab), nomor mahasiswa, jenis tugas, mahasiswa atau mahasiswi, dan kampusnya. Semester ditanya hanya kalau kampusnya معهد العلوم الإسلامية والعربية في جاكرتا (sampul `mahad`). Simpan sebagai baris `@nama:`, `@nim:`, `@jenis:` (dan `@fasl:` + `@sampul: mahad` untuk kampus itu) di berkas itu. `baru` memakainya untuk tiap bahts. Sampul bawaan wajibnya hanya nama, tetapi nomor mahasiswa dan jenis tugas ikut tercetak kalau ada.
- Pemakainya mahasiswi → tambah baris `@thalibah: ya` di `sampul_saya.txt`: sampul mencetak «اسم الطالبة».
- Dosen atau pemakai minta halaman kaligrafi basmalah sesudah sampul → `@basmalah: ya` di naskah: satu halaman ﷽ (huruf Arabic Typesetting, ikut paket huruf Arab yang sama dengan Traditional Arabic) di tengah halaman, tanpa nomor, sebelum الإهداء. Tanpa barisnya = tidak ada halaman itu; jangan menambahkannya tanpa diminta.
- Pembimbing (`@musyrif`, `@jabatan`) ditanya tiap bahts dan ditulis di naskahnya: dosennya bisa berbeda.
- Dosen minta مبحث dan مطلب beda halaman → `@halaman_baru:` berisi tanda مطلب, juga tanda مبحث kalau bukan #F (#F مبحث + #B مطلب → `B`; #B مبحث + #M مطلب → `B, M`). Halaman isi jadi beberapa halaman lebih banyak: isi jangan dipangkas demi jumlah halaman.
- Pemakai memberi Word miliknya sendiri (sampul, kepala halaman bergaris) → simpan di folder bahts, tulis `@templat: <berkas>.docx`: halaman pertamanya jadi sampul apa adanya (`@nama` dkk. tidak tercetak), kepala halamannya dipakai di halaman isi. Isi tetap dari `naskah.txt`.
- Sampul bawaan memakai kop جامعة الإمام dan قسم الشريعة. Beri tahu pemakai sekali; kalau kampusnya lain, minta Word sampul kampusnya lalu pakai `@templat` (di atas); jangan mengubah `mesin/sampul_qism.docx`. Dosen minta sampul معهد العلوم الإسلامية والعربية في جاكرتا، كلية الشريعة → `@sampul: mahad`. Qism lain di sampul bawaan (mis. قسم اللغة العربية) → `@qism:` (« // » = pindah baris); logo berwarna → `@sampul: jakarta`.
- Sampul bawaan = model قسم الشريعة (logo kiri atas, judul besar, sub-judul sampul dalam kurung kalau ada, المشرف, إعداد الطالب, العام الجامعي). Judul = bagian `@judul` sebelum « - », sub-judul sampul = sesudahnya. Judul memakai huruf PT Bold Heading (tidak ikut repo karena lisensinya tidak jelas): belum terpasang → `rakit` mencetak PERINGATAN dan memakai Traditional Arabic tebal; beri tahu pemakai bahwa hurufnya perlu dipasang sendiri. Jenis tugas (`@jenis`, mis. بحث صفي للمستوى الثامن) tercetak di bawah judul dan nomor mahasiswa (`@nim`) di bawah nama kalau diisi; kosong atau `-` = barisnya tidak ada. Semester tidak tercetak; yang wajib hanya `@judul` dan `@nama`. Tahun bawaan = tahun hijriah Umm al-Qura saat tahun ajaran mulai (1 Agustus), jadi satu tahun ajaran tetap satu tahun walau 1 Muharram lewat; dosen minta tahun lain → `@tahun:` (mis. ١٤٤٨).
- `@judul` = judul persis dari dosen, خطة, atau pemakai. Jangan menambah sub-judul sampul sendiri (bagian « - …» di `@judul`, mis. «- دراسة فقهية…» atau «- دراسة مقارنة»): hanya kalau sumber itu menulisnya. Jenjang atau jenis tugas (mis. «المستوى الرابع») masuk `@jenis`, bukan sub-judul. Tanpa sub-judul sampul, sampul tetap rapi karena barisnya tidak tercetak. Ini tidak menyangkut judul `#S` di dalam naskah.
- Nama folder untuk `baru`: pendek, huruf Latin, tanpa spasi (mis. `ikhlas`). Nama berkas hasil diatur `@berkas`.
- Bahts untuk banyak orang: `bahts/<orang>/<topik>` (mis. `baru bahts/ahmad/ikhlas "<judul>"`); `cek`, `rakit`, dan `ambil` memakai jalur yang sama. `<orang>` = nama pendek Latin yang sama untuk orang yang sama; data sampulnya ditulis di naskah, bukan `sampul_saya.txt`: `baru` tidak menyalin `@nama`, `@nim`, `@jenis`, `@fasl`, `@thalibah`, `@sampul` dari `sampul_saya.txt` ke `bahts/<orang>/…`, tetapi dari bahts terakhir orang yang sama kalau ada (pastikan masih benar). Bahts pertama orang itu → tanyakan pertanyaan sampul yang sama dengan `sampul_saya.txt` di atas (nama, nomor mahasiswa, jenis tugas, mahasiswa atau mahasiswi, kampus) ditambah pembimbing, lalu tulis jawabannya di naskahnya; pemberitahuan kop sampul juga untuk orang itu.
- `keluaran_saya.txt` (opsional, satu baris berisi folder) → `rakit` menaruh salinan PDF di sana (`<folder>/ahmad/<berkas>.pdf`). Folder bahts tetap induknya; salinan ditimpa tiap `rakit`.
- Jumlah halaman yang disebut pemakai = halaman isi (المقدمة sampai الخاتمة); `rakit` mencetaknya sebagai `HALAMAN_ISI`; halaman `#K` sebelum المقدمة (الإهداء، الملخص) tidak ikut terhitung. مقدمة, tiap فصل, dan خاتمة selalu mulai halaman baru. Jelaskan ke pemakai bahwa PDF juga memuat sampul, المصادر والمراجع, dan الفهارس, lalu sebut `HALAMAN_ISI` dan `HALAMAN` sesudah `rakit`. Dosen membatasi halaman seluruh PDF (bukan isi) → pakai «seluruh PDF: ±N» dari `cek` (sampul, المصادر, dan فهرس ikut dihitung) sebelum memangkas, lalu pastikan dengan `HALAMAN` sesudah `rakit`; selisih perkiraan biasanya 1-3 halaman.
- Angka di PDF bawaan ٠١٢٣ (dasarnya di README «Standar halaman»). Dosen minta 0123 → `@angka: latin` di naskah. Cuma nomor ayat di catatan kaki yang 0123 → `@angka_ayat: latin`.
- Dosen minta judul 16, matan 14, catatan kaki 12 → `@format: tatbiqi`. Sama, tetapi matan 1,5 spasi dan paragraf الملخص berjarak tanpa awal alinea menjorok → `@format: tatbiqi_15`; hanya bagian الملخص yang 1,5 spasi (matan tetap satu spasi) → `@format: tatbiqi_mulakhas`. Matan 16, catatan kaki 12, spasi 1,5, judul utama 18, sub-judul 16 → `@format: tatbiqi_16`. Halaman sebelum الفصل الأول bernomor huruf → `@nomor: abjad`; nomor ١ diminta mulai المقدمة (yang sebelumnya tetap huruf) → `@nomor: mukadimah`; الإهداء, الشكر, dan الملخص ditulis sebagai `#K` sebelum المقدمة, الملخص bahasa Inggris lewat `#L` (judul «Abstract» tebal di tengah: `#L **Abstract**`). Bait syair → `#V`. Dosen minta جدول (mis. جدول المقارنة) → baris `#J sel | sel | sel` berturut-turut; baris pertama jadi kepala tabel.
- Nomor catatan kaki bawaan mulai ١ lagi tiap halaman. Diminta bersambung sampai akhir bahts → tambah `@catatan_kaki: bersambung` di samping `@format` apa pun (mis. `@format: tatbiqi` + `@catatan_kaki: bersambung`). Matan diminta 1,5 spasi tanpa ubahan الملخص → `@spasi: 1.5` di samping `@format`. Kombinasi seperti itu dibuat dengan kunci timpa ini, bukan profil baru; `imam_ayat16_bersambung` (= `imam_ayat16` + `@catatan_kaki: bersambung`) tetap jalan untuk naskah lama. `@format` hanya satu: dosen minta dua hal yang tidak bisa dibuat dengan satu profil ditambah kunci timpa itu → beri tahu pemakai, jangan pilih sendiri salah satunya.
- خطة dosen menaruh فهرس المصادر والمراجع sesudah فهرس الأحاديث → `@pustaka: akhir`. Bawaan: المصادر والمراجع sebelum فهرس الآيات.
- Pemakai memberi PDF contoh bahts قسم الشريعة بجاكرتا (kepala halaman bergaris dengan nomor berbingkai, فهرس الآيات per surat, فهرس الموضوعات bertitik-titik, pustaka dengan nama pengarang tebal) dan minta ditiru → `@model: jakarta` (+ `@sifat:` baris di bawah nama, mis. «الطالب بقسم الشريعة للفترة الصباحية»). Tiap bagiannya bisa dipilih sendiri dan dicampur dengan model lain (`@kepala`, `@fihris_ayat`, `@fihris_hadits`, `@maudhuat`, `@pustaka_gaya`, `@judul_kanan`, `@fihris`, `@rujukan_ayat`; rinciannya: `tanda`). `@rujukan_ayat: matan` = rujukan ayat dicetak «[المائدة: ٢٧]» di matan sesudah ayatnya, bukan di catatan kaki (naskah tetap ditulis `[^سورة …، آية: n.]`). Dengan `@pustaka_gaya: muallif` tiap baris #R ditulis «**pengarang** (ت …هـ). __judul__. data cetak».
- Dosen minta bahts dikumpulkan bertahap per فصل → tetap satu folder dan satu naskah; tiap potongan dirakit dengan `rakit <folder> --fasl n` (`--fasl 1-2` = dua فصل sekaligus). Jangan menyalin naskah ke folder lain, menyunting potongan lewat skrip, atau membuang halaman PDF: sampul hanya di potongan pertama (bersama المقدمة), المصادر dan الفهارس hanya di potongan terakhir (bersama الخاتمة), nomor halaman tiap potongan mulai ١. Rincian: `tanda`.
- خطة dosen meminta فهرس الأعلام → tulis `{N:nama}` di matan dekat tiap nama tokoh yang disebut (bukan di catatan kaki, bukan Nabi ﷺ), dengan nama yang sama persis tiap kali (mis. `{N:ابن القيم}`, `{N:آل بورنو، محمد صدقي}`); `rakit` mencetaknya sesudah فهرس الأحاديث. Tanpa `{N:}` = tidak ada فهرس itu.
- Pemakai tidak mau فهرس tertentu → `@tanpa:` di naskah (`ayat`, `hadits`, `alam`, `maudhuat`; mis. `@tanpa: ayat, hadits`). Dosen minta sumber cukup di catatan kaki → `@tanpa: pustaka` dan tanpa `#R`. Jangan membuangnya tanpa diminta.
- Laporan akhir ke pemakai: tulis letak lengkap berkas PDF-nya. Sebelumnya `tahap <folder>` harus mencetak `TERKINI` untuk PDF yang dilaporkan (dirakit dari naskah.txt terakhir; bahts bertahap: potongan yang baru dirakit); `USANG` = naskah diubah sesudah `rakit`, `TIDAK_DIKETAHUI` = laporan dari mesin versi lama: rakit ulang dulu.

## Alur kerja

Sesi baru, atau tidak tahu bahts ini sampai mana → `tahap <folder>` dulu, jangan menebak dari berkas di folder: ia membaca ulang naskah (`NASKAH=` GAGAL/PERHATIAN/LOLOS), hasil rakit (`HASIL=` BELUM/TERKINI/USANG/TIDAK_DIKETAHUI, juga tiap `--fasl`), rakit yang sedang jalan (`RAKIT=`), folder `.rakit-*`, dan cadangan `_arsip/rakit-*`, lalu mencetak satu `BERIKUTNYA`. Baris `PERLU PEMAKAI` → sebut ke pemakai, jangan dihapus sendiri.

1. `baru`, lalu susun خطة (فصل/مبحث/مطلب) sesuai permintaan dosen. خطة dosen menyebut isi المقدمة (mis. تساؤلات الدراسة) → sub-judul المقدمة ikut itu.
2. Kumpulkan bahan; kutip hanya dari teks yang benar-benar terbaca di kitab lokal.
   Belum tahu kitab mana yang membahas → `temukan "<frasa>"` (isi semua kitab Shamela lewat turath.io, tanpa akun; `--mazhab hanbali` hanya kitab fikih mazhab itu, `--kitab <id>` hanya kitab itu walau belum diunduh, `--halaman 2` hasil ke-21 dst.; berjatah, jadi jangan dipanggil ratusan kali berturut-turut), `katalog` (judul/pengarang), dan alat connector `shamela` (wajib; terdaftar di `.mcp.json`) (shamela.link: seluruh kitab Shamela, nomor kitabnya sama dengan `ambil`). Connector hanya penunjuk jalan: kitabnya tetap di-`ambil`, kutipannya tetap harus lolos `cek`. Balasan «server … is restarting» atau galat sementara lain: ulangi sekali sesudah beberapa detik; masih gagal → jalur cadangan di bawah. Batasnya: tidak resmi, butuh akun pemakai sendiri, berkuota, hasil kosong di sana bukan bukti tidak ada, dan subjek pencarian harus frasa pendek persis seperti di kitab.
   Kuota `shamela` habis atau layanannya mati sesudah bahts dimulai → lanjut lewat connector `turath` (`search_turath`): `cat_id` 14 حنفي، 15 مالكي، 16 شافعي، 17 حنبلي (sama dengan `temukan --mazhab`), `book_id` sama dengan nomor `ambil`, hasilnya paling banyak 10 halaman. Alat ini tidak punya status `silent`: «mazhab ini diam» tidak boleh disimpulkan darinya. Pengganti `shamela_research_scope`/`shamela_scan_consensus` tidak ada: ijmak dan «tidak ditemukan» ditulis hanya dari teks yang dibaca, atau dilaporkan «belum dicek». Takhrij tetap lewat `hadits` dan connector `hadithunlocked`; langkah wajib `shamela_search_phrase` kategori 8 dilaporkan «belum dicek». Laporan akhir menyebut bagian mana yang dicari lewat `turath` sebagai ganti `shamela`. MCP resmi shamela.ws (`mcp.shamela.ws`) sengaja tidak dipasang: pencariannya mengurutkan kecocokan kata, bukan frasa persis, sehingga frasa karangan pun berhasil (angkanya di `dok/uji-riset.md`).
   Sebelum mengumpulkan bahan, cari dulu alat connector yang tersedia dengan pencari alat agentmu (Claude Code: ToolSearch «shamela», «turath», «tafsir», «hadith», «quran»); yang tidak dicari tidak terlihat, dan awalan namanya bisa berbeda (lihat Pemakai baru langkah 4). Alat connector `shamela` wajib dipakai: untuk tiap مبحث, cari dulu istilah kuncinya di sana sebelum menulis, juga kalau kitab lokal terasa sudah cukup (`cari <id>` hanya melihat kitab yang kamu sebut; connector melihat semuanya). Masalah khilaf → `shamela_research_scope` (isi `synonyms` kalau mazhab lain memakai istilah lain) sebelum menulis pendapat tiap mazhab: hanya baris `silent` yang boleh jadi dasar «mazhab ini diam», dan `found` hanya berarti tiap kata istilah itu ada sehalaman, jadi pastikan frasanya dengan `shamela_search_phrase`; lalu `shamela_scan_consensus` sebelum menulis ijmak atau khilaf: angkanya hanya tempat mencari, baca saksinya. Ayat yang dibahas → baca tafsirnya lewat connector `tafsir` (kalau ada) sebelum menulis, lalu `ambil` kitab tafsirnya. Laporan akhir menyebut alat pencari yang dipakai dan yang tidak, serta versi naskah yang diperiksa (`NASKAH_SHA256` dari `cek`).
   Langkah wajib di bawah ini tidak meninggalkan jejak di kitab lokal, jadi `cek` tidak bisa melihatnya. Catat tiap langkah di `riset.txt` folder bahts begitu dijalankan (`baru` membuatnya; bentuk barisnya: `python mesin/bahts.py tanda`). Yang belum tercatat jadi perhatian `cek`:
   1. Tiap hadits `{H:}` → `shamela_search_phrase` kategori 8 (lihat Takhrij di bawah) → `takhrij8 <kunci>`.
   2. Tiap ayat `{Q:}` → baca tafsirnya lewat connector `tafsir` → `tafsir <surat:ayat>`.
   3. Tiap masalah khilaf (bagian berjudul yang barisnya diawali «القول الأول»، «الرأي الأول»، atau «المذهب الأول») → `shamela_research_scope` → satu baris `khilaf <istilah>` per masalah.
   Langkah yang tidak bisa dijalankan (layanan mati, kuota habis) → `belum <langkah> <objek> <alasan>`, lalu sebut di laporan akhir. Jangan menulis baris untuk langkah yang tidak benar-benar dijalankan.
   Jangan menyatakan bahan cukup sebelum persoalan dalam rencana, termasuk syarat dan pengecualiannya, terdukung oleh konteks sumber yang dibaca; cari lintas bab/kitab bila ada celah.
   Konteks = bab tempat halaman itu berada, bukan halaman hasil cari saja. Sebelum mengutip atau menisbatkan pendapat dari satu halaman kitab, baca seluruh bab-nya sekali. Yang dicari di bab: siapa yang berkata, syarat dan pengecualiannya, dan pendapat lain yang dibantah. Urutannya (angka ujinya di `dok/uji-riset.md`):
   1. Kitab sudah di-`ambil` → `bab <id> "<frasa>"` untuk judul bab-nya, lalu `halaman <id> <juz> <a-b>` (paling banyak 20 halaman sekali panggil) mundur sampai judul bab itu dan maju sampai judul bab berikutnya (judul biasanya tercetak dalam kurung siku, mis. «[بَابُ الْخِيَارِ فِي الْبَيْعِ]»).
   2. Belum di-`ambil` → connector `shamela`: `shamela_get_toc` dengan `containing_page_id`, `shamela_get_book_section` dengan `title_id` bab terakhir di rantainya, lalu `shamela_get_pages_range` mulai `next_start_page_id` sampai `end_page_id` dari `get_book_section` (`has_more` tetap true sesudah bab habis).
   Kitab tetap dikutip dari teks lokal; `cek` tetap putusan. Membaca bab tidak meninggalkan jejak yang bisa dilihat `cek`, jadi pemeriksa langkah 5 yang menilainya.
   Sebelum memperbanyak panggilan atau menyimpulkan dari hasil alat, pastikan cakupan, kolom hasil, dan batas tampilannya benar; buka detail/halaman berikutnya bila pertanyaan belum terjawab.
   Urutan mencari (angka ujinya di `dok/uji-riset.md`). `shamela_search_phrase` tanpa `scope` bukan pencarian utama: hasil teratasnya jarang kitab mu'tamad.
   Khilaf: (1) `shamela_research_scope` dengan sinonimnya; hanya alat ini yang memberi status `silent`. (2) Untuk tiap mazhab, `shamela_search_phrase` dengan `scope.book_ids` dari `dok/mutamad.md`, `limit` 100, lanjutkan `offset` sampai `has_more` false, ulangi untuk istilah lain masalah itu dan kata tunggal yang spesifik (`الجوار`, bukan `الشفعة`), karena frasa `بيع العربان` tidak menangkap «وكبيع العربان». (3) `shamela_search_titles` dengan `scope.category_ids` mazhab itu (14 حنفي، 15 مالكي، 16 شافعي، 17 حنبلي). (4) Sebelum menulis «tidak ditemukan», `shamela_search_pages` dengan `options: {wildcards: true}` (mis. `*عربان`). Hasil kata tunggal dan wildcard wajib dibaca: `*عربان` juga cocok dengan suku «العربان».
   Takhrij: `hadits`, lalu selalu `shamela_search_phrase` dengan `scope.category_ids: [8]` (`التخريج والأطراف`) walau `hadits` sudah memberi nomor dan hukum; `hadits` 0 hasil → tambah `search_hadith`. Kolom `takhrij` di `shamela_search_hadith` jangan diandalkan.
   Tafsir: `shamela_list_tafsirs_for_aya` untuk `book_id` dan `page_id` yang bisa di-`ambil`, lanjutkan `offset`; kitab berstatus `not_indexed_coverage_unknown` belum tentu kosong. Teksnya dibaca lewat `fetch_tafsir`, tiap `part` sampai `has_more` false, karena teks panjang dipotong.
   Adab dan tarajim: `shamela_search_titles` tanpa `scope`, lalu `shamela_search_phrase` dengan `scope.category_ids` 25, 26, 32, `limit` 100, mulai dari nama lengkap (`أبو الطيب المتنبي`) sampai `has_more` false, lalu nama lainnya. Nama pendek yang hasilnya ribuan: cukup 4 halaman tiap kategori, dan baca hasilnya, karena `المتنبي` juga cocok dengan المتنبئ.
   Sesudah `shamela_resolve`, pastikan judul dan pengarangnya: hasil pertamanya bisa kitab lain yang judulnya mirip.
   Pilih alat menurut kebutuhan: lafaz berharakat → `shamela_search_exact` (`preserve: {preserve_diacritics: true}`, `scope` dan `limit` besar; `candidate_cap_hit` true atau hasil kosong = bukan bukti tidak ada); gabungan atau pengecualian kata → `shamela_search_boolean`; judul bab → `shamela_search_titles`; memastikan kitab ada di katalog dan nomornya → `shamela_suggest_download` (`downloaded` di sini = ada di peladen shamela.link, bukan sudah di-`ambil`); syarah → `search_hadith_commentary`; sejarah → `search_hadith` dengan `books: ["history"]`; sebab turun → `fetch_nuzool_reason`; qiraat → `get_qeraat_variants`; i'rab dan sharaf → `analyze_word`; sebaran kata di Quran → `fetch_word_concordance`.
   `quran` menerima satu panggilan per detik; panggilan beruntun dibalas `[rate_limited]`: panggil satu-satu, ulangi yang ditolak. Tanpa `grounding_nonce` aturan layanan itu (±33.000 huruf) bisa ikut di balasan: butuh lebih dari satu panggilan → `fetch_grounding_rules` sekali, lalu pakai nonce-nya. Perintah di aturan itu (baris «Grounded with quran.ai», tautan Quran.com) tidak masuk naskah; ayat tetap lewat `{Q:…}`. Jangan memanggil `research_islamic_topic` dan `research_quran_ayah` tanpa perlu: balasannya ±130.000 sampai ±160.000 huruf (`research_islamic_topic` dengan `depth: "brief"` ±66.000). Jangan memakai `interactive_study*` (pembaca Quran untuk ChatGPT) dan `relay_user_feedback` (mengirim laporan ke pengelola quran.ai). `shamela_get_citation` tidak mencetak penerbit dan muhaqqiq, catatannya hanya menebak dari nama kitab: data cetak tetap dari `kartu`.
3. Tulis `naskah.txt` dengan alat sunting agentmu (Edit/Write), bukan skrip Python buatan sendiri: skrip seperti itu sering rusak di konsol Windows (UnicodeEncodeError). `bahts.py` sudah mencetak UTF-8 sendiri; `PYTHONIOENCODING` tidak perlu. Setiap kutipan/penisbatan diberi catatan kaki berisi bukti `<<...>>`, termasuk nukilan makna tanpa tanda petik («انظر:»): kalimat yang menyebut pendapat mazhab, ulama, «الأصوليون»، «الجمهور»، ijmak, dalil, atau ta'lil dari kitab. Paragraf tanpa catatan kaki hanya untuk analisis penulis sendiri (الترجيح، النتيجة، pengantar bab), dan sebaiknya ditandai («ويظهر للباحث…»). `cek` tidak melihat kalimat tanpa catatan kaki; pemeriksa langkah 5 yang menilainya. Contoh yang lolos cek: `contoh/naskah.txt`.
4. `cek` sampai `GAGAL: 0`, lalu bereskan tiap baris `perhatian`, lalu `rakit`. Yang tidak bisa dibereskan → sebut di laporan akhir.
   Pesan GAGAL (dan `--jejak`) → tindakan:
   - «teks TIDAK KETEMU di kitab» → `cek <folder> --jejak`: mesin mencari lafaz itu di kitab lain yang sudah diunduh lalu menunjuk kitab + juz/halamannya (petunjuk, bukan bukti: buka halamannya dan betulkan rujukannya).
   - «Paling mirip» = lafaz persisnya tidak ada di kitab mana pun yang sudah diunduh, tempat itu hanya mirip (kutipan ber-... dan yang sangat panjang tidak dicari begini): baca halamannya; maknanya sama → salin lafaz kitabnya; berbeda → kutipannya dibuang, bukan disesuaikan.
   - Tidak ada kitab yang ditunjuk → `shamela_verify_quote` tanpa `book_id`, `limit` 20: `--jejak` hanya melihat kitab yang sudah diunduh, alat itu seluruh Shamela, tetapi kutipan yang menyambung dua halaman bisa terlewat dan `not_found` bukan bukti tidak ada. Kitabnya lalu di-`ambil` dan rujukannya harus lolos `cek`. Hasil alat itu:
     - `partial` = kutipan itu tidak ketemu: jangan menulis ulang kutipan mengikuti halaman yang ditunjuk.
     - `differs` = seluruh kutipan ada, bedanya disebut (harakat, hamzah, angka): salin lafaznya dari kitab yang dirujuk.
     - kutipan yang ditemukan di `foot` = حاشية المحقق, bukan perkataan pengarang.
     - tidak semua calon tempat diperiksa, jadi `verbatim` pun bisa bukan sumber aslinya; kutipan pendek atau masyhur dipersempit dengan `scope`.
     - `page_id` di alat itu nomor urut Shamela, bukan nomor cetak; juz/halaman di naskah tetap nomor cetak.
   - «sebut bagiannya» = kutipan itu ada di halaman yang sama di dua bagian kitab: tulis bagiannya (<<id|الكتاب|5>>; «ص5» di catatan kaki tetap cukup).

   `perhatian` → tindakan (`GAGAL: 0` belum berarti naskah selesai):
   - judul «tercetak sendirian» = tulis paragraf pengantar: kaitannya dengan bagian sebelumnya dan isinya (وفيه مطلبان…), tanpa klaim baru tanpa bukti.
   - judul «langsung disusul judul …» (فصل/مبحث yang langsung ditumpuk مبحث/مطلب-nya) = sama dengan «tercetak sendirian».
   - bagian «… masih kosong» = judul itu belum punya paragraf isi sebelum judul berikutnya yang setingkat atau lebih tinggi (mis. kerangka dari `baru` yang belum diisi): tulis isinya, atau hapus judulnya kalau memang tidak dipakai.
   - bukti di حاشية المحقق atau di bagian tulisan muhaqqiq/penerbit (مقدمة الطبعة، مقدمة التحقيق، ترجمة المؤلف…) = kalimat muhaqqiq, jangan dinisbatkan ke pengarang kitab.
   - «diantar «قال الشافعي:»» = di kitab itu ucapan orang lain: nisbatkan ke dia lewat perantara (نقل البهوتي عن الشافعي) atau buang penisbatannya.
   - kitab «مرقم آليا» = nomor halamannya bukan nomor cetakan, `ambil` edisi yang «موافق للمطبوع».
   - kutipan tanpa catatan kaki sendiri = beri catatan kaki berbukti atau buang tanda petiknya.
   - kata nafi (لا/ما/ليس) tepat sebelum kutipan di kitab, atau kutipan menafikan yang di kitab disambung «إلا» = pastikan maknanya tidak terbalik (pengecualiannya ikut dikutip).
   - angka di kutipan yang tidak terbaca di halaman itu = salin angkanya dari kitab.
   - nomor takhrij bukan kepala hadits atau lafaz bukti di hadits lain = buka kitabnya, betulkan nomor atau buktinya (nomor dibaca dengan atau tanpa kurung: «رقم الحديث (n)», «برقم n», «رقم: n», sebelum `juz/hal` atau `ص h`).
   - derajat hadits belum ditulis = tulis derajat dan penghukumnya dari kitab yang dibaca (lihat aturan takhrij).
   - derajat tidak terbaca di halaman bukti = beri bukti kitab yang menghukuminya, atau betulkan derajatnya.
   - sebagian kata طرف `{H:}` tidak terbaca = salin طرف dari lafaz hadits yang dikutip.
   - rawi `{H:}` tidak terbaca di halaman bukti = pastikan sahabat perawinya di kitab.
   - catatan kaki menyebut kitab lain sementara buktinya syarah/hasyiah = tulis kitab yang benar-benar dibaca atau sebut perantaranya.
   - kutipan dipotong `...` = baca yang dilompati, pastikan makna dan pembicaranya tetap.
   - «kutipan bersisipan [ ] yang menggantikan teks kitab» = kata kitab diganti kata dalam kurung siku: pastikan yang diganti memang salah, dan maknanya tetap.
   - «kutipan memuat tambahan penulis» = kurung siku yang tidak membetulkan apa pun: pindahkan penjelasannya ke luar kutipan atau ke catatan kaki.
   - «urutan sumber» = urutkan kitab di catatan kaki «انظر:» dari pengarang yang lebih dulu wafat.
   - «rujukan pertama … tanpa data cetak» = salin data cetak kitab itu dari `kartu` ke catatan kaki pertamanya (mesin mencocokkannya ke penerbit, muhaqqiq, atau tahun cetak di `kartu` kitab itu sendiri); rujukan berikutnya tetap ringkas. Kitab hadits (كتب السنة) dan takhrij tidak dinilai: data cetaknya di المصادر.
   - «beberapa sumber dipisah «،»» = ganti pemisah antarsumber dengan «؛» (takhrij «أخرجه … ، و…» tidak termasuk).
   - «gelar … di depan nama» = buang gelarnya (د.، أ.د.، الدكتور، الشيخ، العلامة، فضيلة…); `kartu` membuang gelar di awal nama, jadi data yang disalin darinya tidak ditandai. «الإمام»، «المحدث» dan jabatan di belakang nama («الأستاذ المساعد») tidak dinilai.
   - «الخاتمة belum menyebut النتائج» = tulis hasil penelitian di الخاتمة («أهم النتائج: …»); التوصيات tidak wajib.
   - «المقدمة belum menyebut: …» (hanya رسالة/بحث تكميلي) = tulis isi yang diminta خطة dosen; yang tidak diminta dibiarkan dan disebut di laporan akhir.
   - «N kata berurutan di luar tanda petik sama persis dengan halaman buktinya» = kalimat itu memuat deret lafaz kitab: beri tanda petik lalu buang «انظر:», atau tutup kitabnya dan tulis ulang gagasannya dengan kalimat sendiri, lalu cocokkan lagi ke halamannya (ص113). Mengganti satu-dua kata supaya perhatiannya hilang = salah. الاختصار yang memang memakai kata pengarang (ص114: daftar istilah, butir syarat) boleh dibiarkan dan disebut di laporan akhir; batas 8 kata aturan repo, lebih ketat dari kitabnya. Deret nama dan sanad tidak ditandai.
   - «nukilan makna tanpa «انظر:»» = awali catatan kakinya «انظر:» atau «راجع:» (ص114، 173); kalau kalimatnya memang lafaz kitab, beri tanda petik.
   - «kutipan lafaz … dirujuk «انظر:»» = buang «انظر:»: kutipan yang hanya diantar «قال …:» dirujuk langsung ke kitabnya (aturan repo; mesin hanya mengenali pengantar «قال/يقول»).
   - «kutipan N kata … lebih dari 60 kata» = kutip lafaz kuncinya saja dan ringkas sisanya dengan «انظر:»; nash yang memang harus utuh (Cara menukil nomor 2) dibiarkan dan disebut di laporan akhir.
   - «… hurufnya kutipan bertanda petik» = ringkas sebagian kutipan bagian itu dengan «انظر:» lalu tulis pembahasan sendiri di antaranya; isi jangan dipangkas.
   - rujukan kitab tanpa bukti = buka halamannya di kitab, lalu tulis `<<sid|juz|hal>>` (sumber di luar Shamela → `<<luar>>`).
   - «ayat dipotong: kitab mengutip lebih panjang» = `{Q:}` mencetak lebih pendek dari ayat yang dikutip kitab: cetak sebatas lafaz kitab (`{Q:s:a:i-j}`) kecuali potongannya memang tidak mengubah makna.
   - «standar sumber» = cari pendapat itu di kitab mazhabnya sendiri, atau ijmak itu di kitab ulama yang menukilnya, lalu ganti buktinya (bagian «Standar sumber»); asalnya tidak ada → «نقلا عن …» di catatan kaki dan sebut di laporan akhir.
   - `<<luar>>` = cocokkan lafaz dan halamannya ke berkas sumbernya (punya PDF-nya → pakai `<<luar|berkas.pdf|hal>>` supaya mesin menunjuk halamannya).

   Keluaran `rakit` tidak perlu disaring (`grep`): `cek` yang lolos dicetaknya satu baris (jumlah perhatian), yang GAGAL lengkap.
5. Sebelum lapor selesai: minta subagent baru (yang tidak ikut menulis) membuka sendiri halaman kitab tiap catatan kaki dan menilai PDF hasil (tanpa `rakit`: naskah yang sudah lolos `cek`) terhadap permintaan awal + aturan di bawah, termasuk apakah tiap baris `riset.txt` cocok dengan alat yang benar-benar dipakai dan apakah `@judul` sama persis dengan judul dari dosen, خطة, atau pemakai (tanpa sub-judul sampul tambahan); perbaiki temuannya; `cek` dan rakit ulang. Satu putaran pemeriksa penuh per bahts; sesudah temuannya dibereskan, pemeriksaan ulang hanya untuk catatan kaki dan bagian yang diubah, bukan seluruh bahts lagi (di transkrip, pemeriksa ulang penuh menghabiskan waktu paling banyak dari semua tahap). Agentmu tidak bisa membuat subagent → minta pemakai membuka sesi agent baru di folder ini dan menempel permintaan pemeriksaan itu; hasilnya kamu bereskan.
   Pemeriksa juga menilai apakah isi tiap kutipan cocok dengan bab tempatnya (pembicara, syarat, pengecualian; Alur kerja langkah 2, «Konteks = bab»), dan tiap catatan kaki terhadap tabel «Standar sumber»: apakah ada sumber yang lebih tinggi untuk klaim itu (kitab mazhabnya sendiri, kitab ulama yang dikutip, kitab asal hadits, sumber tertua), dan apakah tiap «مقتبس من»/«نقلا عن» memang karena asalnya tidak bisa didapat. Wajib juga, di putaran penuh: tiap baris «tanpa catatan kaki» dari `bukti` (paragraf isi tanpa catatan kaki) dinilai satu per satu. Paragraf yang memuat penisbatan, ijmak, dalil, ta'lil, atau fakta yang diambil dari kitab tanpa sumber = temuan, dan penulis memberinya catatan kaki dari kitab yang dibaca; yang tidak ada di kitab dihapus atau ditulis sebagai pendapat penulis. Begitu juga catatan kaki «انظر:» yang hanya mendukung sebagian kalimatnya. Hasilnya disebut di laporan pemeriksa, walau «tidak ada». Rujukan kedua dan seterusnya dari kitab yang sama cukup ringkas, tanpa data cetak lagi (أبو سليمان ص170); `cek` tidak menilainya.
   Pemeriksa juga menilai tiap nukilan makna («انظر:») terhadap halaman buktinya: التلخيص dan الاختصار «يقابل ما يكتب مع ما جاء في الأصل» (أبو سليمان ص114). Tiga hal: gagasannya memang ada di halaman itu, syarat dan pengecualiannya ikut, dan kalimatnya bukan lafaz kitab yang hanya diganti beberapa katanya (ص113). Mesin hanya menangkap deret 8 kata yang sama persis; yang lebih halus, dan nukilan makna dari sumber `<<luar>>`, tugas pemeriksa. Paragraf tanpa catatan kaki yang isinya «المعلومات البدهية» (istilah yang disepakati, ungkapan umum) tidak perlu sumber (ص176) dan bukan temuan. Sesudah itu naskah dibaca sekali dari awal dengan tujuh butir مراجعة المسودة (ص194-195): urutan dan kaitan gagasan, kaitan sub-judul dengan judulnya, rumusan judul, keseimbangan panjang antarbagian, sikap adil terhadap pendapat yang berlawanan, kutipan yang cocok dengan tempatnya dan diberi pengantar, dan bentuk rujukan.
   Pemeriksa membuka halaman kitab lewat `bukti <folder>` dulu (pemeriksaan ulang: `bukti <folder> <awal-akhir>` untuk baris yang diubah): sekali jalan, tiap catatan kaki berbukti mencetak kalimat yang dibuktikan, isi catatan kakinya, nama kitab, bab, dan teks halaman itu di sekitar letak kutipannya; tiap `{Q:}` mencetak teks ayat persis seperti tercetak; tiap paragraf isi tanpa catatan kaki dicetak sebagai «baris n tanpa catatan kaki: «…»». Baru `halaman <id> <juz> <hal>` untuk yang perlu dibaca lebih luas (siapa yang berkata, apa yang dilompati `...`). Jangan memanggil `halaman` satu per satu untuk tiap catatan kaki, dan jangan menulis skrip sendiri yang mengimpor `mesin/olah.py`.

`cek` hanya membuktikan bahwa teksnya ada di juz/halaman itu. Nama kitab yang tercetak hanya dijaga sebagian: catatan kaki yang menyebut judul katalog kitab lain di tempat judul, mukharrij lain sesudah «أخرجه/رواه», atau pengarang katalog lain di tempat pengarang, tanpa menyebut judul atau pengarang kitab buktinya = GAGAL (judul katalog kitab lain tetap GAGAL walau pengarangnya sama); judul kitab bukti dengan pengarang katalog lain = perhatian; `{H:}` yang طرف-nya tidak terbaca di kutipan dan halaman buktinya = GAGAL. Pembicaranya dijaga sebagian saja, sebagai perhatian: kutipan di حاشية المحقق atau di bawah judul tulisan muhaqqiq/penerbit di daftar isi kitab, dan kutipan yang naskah nisbatkan ke pengarang («قال البهوتي:») padahal di kitab tepat diantar «قال <orang lain>:». `cek` TIDAK bisa menilai: apakah yang berkata memang orang itu di luar dua hal tadi (matan yang disyarah, nukilan pihak lain tanpa pengantar «قال …:» tepat sebelum kutipan, hujah lawan, judul muhaqqiq yang tidak dikenali), apakah judul yang disingkat atau dikenali lewat pengarangnya memang kitab buktinya, apakah kitabnya mu'tamad di mazhab yang dinisbatkan, apakah nukilan makna («انظر:») setia pada halaman buktinya (bukti berpotongan hanya membuktikan potongannya, bukan kalimat yang dirujuk), dan kutipan yang tidak diberi catatan kaki. Itu tugas langkah 5.

## Standar sumber (selalu yang tertinggi)

Dasarnya kitab metodologi عبد الوهاب أبو سليمان، «كتابة البحث العلمي صياغة جديدة» (Shamela 8350; baca `halaman 8350 - 70-73` dan `162-163`). Isinya, menurut kitab itu:
- المصدر الأساسي = «أقدم ما يحوي مادة عن موضوع ما»; karya seorang ulama adalah sumber asli untuk pendapatnya. Syarah, hasyiah, ringkasan, dan kajian atasnya = مصدر ثانوي/مرجع (ص70-71).
- Buku modern tentang masalah lama «لا يمكن عدها مصادر»; dipakai استئناسًا, kecuali untuk «مناقشة لفكرة معروضة، أو نقدًا، أو استحسانًا لها» (ص72).
- Satu hal punya beberapa sumber → catatan kaki memakai yang tertua. Yang lebih baru dipakai kalau yang lama hilang, berupa manuskrip yang tak bisa didapat pembaca, yang baru memuat sisi yang tidak ada di yang lama, atau punya kelebihan tertentu; beberapa sumber diurutkan dari pengarang tertua (ص73).
- Menukil lewat perantara (karena asalnya tidak bisa didapat) ditandai «مقتبس من …» (ص162-163). Repo ini juga menerima «نقلا عن …».

Turunannya untuk bahts (aturan repo, bukan teks kitab itu):

| Klaim | Sumber yang dipakai | Perantara (hanya kalau asal tidak bisa didapat) |
|---|---|---|
| Pendapat mazhab | kitab mu'tamad mazhab itu (`dok/mutamad.md`) | kitab mazhab lain, fiqh muqaran, ensiklopedi |
| Ijmak, ittifaq, jumhur | kitab ulama yang menukilnya, dengan nama penukilnya | kitab modern |
| Ucapan seorang ulama | kitab ulama itu sendiri | kitab yang menukilnya |
| Hadits | kitab asal hadits (`أخرجه …`) + derajat dari muhaddits | kitab takhrij hanya untuk derajat |
| Tafsir ayat | kitab tafsir yang menafsirkannya | — |
| Makna kata | معاجم اللغة | — |
| Masalah kontemporer | keputusan المجامع/هيئة asli, penelitian | — |

`cek` menjaga dua baris pertama sebagai perhatian «standar sumber». Batas «modern» = pengarang wafat 1350 H ke atas, atau tahun wafatnya tidak tercatat di Shamela (masih hidup, kolektif, tidak diketahui):
- Kalimat yang menisbatkan pendapat ke mazhab (الحنفية، المالكية، الشافعية، الحنابلة، أبو حنيفة، قال مالك، الشافعي، الإمام أحمد…) dengan bukti kitab fikih, tanpa satu pun bukti dari kitab mazhab itu (daftar `dok/mutamad.md`, atau kitab lama di kategori Shamela mazhab itu) di bagian yang sama. Bagian = sampai judul atau «القول/الرأي/المذهب …» berikutnya, jadi «القول الأول: … وبه قال المالكية والحنابلة» lalu kutipan الدسوقي dan المرداوي di baris berikutnya tidak ditandai. Mazhab yang disebut di dalam kutipan kitab lama adalah ucapan pengarangnya dan tidak dihitung; kutipan dari kitab modern tetap dihitung. Kalimat yang sudah menyebut perantaranya di matan («ذكر ابن قدامة أن…»، «نقل…») atau sedang membantah dalil («ونوقش…») tidak ditandai untuk mazhab; untuk ijmak tetap ditandai, karena ijmak diminta dari penukil tertuanya.
- Ijmak/kesepakatan/jumhur dengan bukti kitab fikih atau usul modern saja.
- Tidak dinilai: catatan kaki takhrij (`أخرجه`/`رواه`) dan ayat, masalah kontemporer (مجمع، قرار، هيئة…), catatan kaki yang menyebut «مقتبس من …»/«نقلا عن …» diikuti nama sumbernya (bukan sekadar «الحنفية» atau «غيره»), kitab usul/akhlak/tafsir untuk pendapat mazhab, dan kitab yang datanya tidak terbaca.

Bereskan dengan mencari di kitab asalnya (`shamela_search_phrase` dengan `scope.book_ids` mu'tamad, `cek --jejak`, `shamela_verify_quote`) lalu ganti buktinya. Asalnya memang tidak bisa didapat → «مقتبس من …» di catatan kaki dan sebut di laporan akhir; menulisnya tanpa mencari dulu tetap dinilai pemeriksa langkah 5. Baris tabel lainnya hanya dinilai pemeriksa langkah 5.

## Aturan penulisan (tidak dijaga mesin)

- Ayat selalu lewat `{Q:…}`; catatan kakinya: `سورة …، آية: n.`
- Mencari tempat hadits dan siapa yang menghukuminya: `hadits "<طرف>"`. Itu penunjuk jalan dan datanya bisa salah: كتاب, باب, nomor, juz/halaman, dan derajat tetap ditulis dari kitab yang dibaca sendiri. Juz/halaman layanan bisa dari edisi lain; kitab yang sudah diunduh diberi baris «edisi lokal <id>: juz/hal»: buka halaman itu, jangan menyalin juz/halaman layanan.
- `cari`, `teks`, dan `bab` mencocokkan kata utuh; baris «N tempat lain hanya cocok sebagai potongan kata» = tempat yang menyeberang batas kata («العرب ان» untuk «العربان»), tidak perlu dibaca. Mencari awal kata («مسح الخف» untuk «مسح الخفين») → `--potongan`.
- Takhrij hadits: `أخرجه البخاري، كتاب …، باب …، رقم الحديث (n)، juz/hal.` (kitab satu jilid: `رقم الحديث (n)، ص h`); di luar Shahihain wajib sebut derajatnya beserta siapa yang menghukumi. `cek` menjaganya: catatan kaki «أخرجه/رواه …» di luar Shahihain tanpa kata derajat (صحيح، حسن، ضعيف، موضوع، منكر, termasuk صححه/حسنه/ضعفه) = perhatian; derajat yang ditulis harus terbaca di halaman bukti, di matan atau حاشية hadits nomor itu, atau di halaman bukti lain catatan kaki itu (mis. «وصححه الألباني في صحيح الجامع» + `<<…>>` ke kitab itu). Yang terbaca di sana hanya derajat lawannya = GAGAL. Derajatnya memang tidak ditemukan → tulis terus terang «ولم أقف على حكم …» dan sebut di laporan akhir. Satu catatan kaki takhrij boleh memuat beberapa bukti; kutipan sebelum catatan kaki dicek ke TIAP bukti `<<sid|juz|hal>>` tanpa potongan, jadi kitab yang lafaznya dikutip ditulis tanpa potongan, riwayat berlafaz lain dan derajat dari kitab lain ditulis berpotongan lafaz yang ada di halaman itu, mis. `[^أخرجه أبو داود، …، رقم الحديث (3502)، 3/283، وابن ماجه، …، رقم الحديث (2192)، 2/738، وهو حديث ضعيف، ضعفه النووي في المجموع، 9/335. <<1726|3|283>> <<1198|2|738|نهى عن بيع العربان>> <<2186|9|335|فالحاصل أن هذا الحديث ضعيف>>]`. Juz bukti mengikuti baris «bukti:» di `kartu` (kitab berjilid yang halamannya bersambung tetap ditulis juz-nya). Catatan kaki hadits cukup takhrij itu; data cetak kitab haditsnya (muhaqqiq, penerbit, cetakan) ditulis di المصادر والمراجع.
- Rujukan pertama sebuah kitab selain kitab hadits yang ditakhrij: data lengkap (judul, pengarang, muhaqqiq, penerbit-kota, cetakan-tahun, juz/hal) — ambil dari `kartu` (tanpa gelar: «إلغاء الألقاب»، أبو سليمان ص175-176). Berikutnya ringkas: `judul، pengarang، juz/hal.` Beberapa sumber untuk satu hal dipisah «؛» (ص176): `انظر: المغني، ابن قدامة، 7/43؛ الإنصاف، المرداوي، 7/43.` Pemisah takhrij («أخرجه أبو داود، …، وابن ماجه، …») tetap «، و». Dengan `@pustaka_gaya: muallif`, المصادر diurutkan menurut nama pengarang tanpa «ال/ابن/أبو» (ابن القيم di ق; ص204).
- Masalah khilaf: cari di kitab mu'tamad tiap mazhab, bukan satu atau dua saja (daftar awal: `dok/mutamad.md`). Abu Sulaiman (ص189): penulisan satu فصل atau موضوع didahului «عرض محرر ومركز للموضوع» sebelum «عرض الآراء والاختلافات ومناقشتها». Aturan repo: tiap masalah khilaf dibuka gambaran masalahnya (صورة المسألة، تحرير محل النزاع) sebelum pendapat pertama. Susun per pendapat, bukan per mazhab: «القول الأول: … وبه قال الشافعية والحنابلة», lalu dalilnya. Pendapat mazhab yang hanya ditemukan di kitab mazhab lain → sebut perantaranya dan tulis di laporan akhir; begitu juga mazhab yang tidak ditemukan.
- Salah di kitab yang dikutip: salin apa adanya lalu tulis «[هكذا]» sesudahnya, atau tulis kata yang benar di dalam kurung siku. Kutipan yang dibetulkan tanpa kurung siku tidak lolos `cek`. Penjelasan ditulis di luar kutipan, bukan di dalam kurung siku.
- Kamus yang tersusun menurut huruf (لسان العرب، الصحاح، القاموس المحيط…) boleh dirujuk lewat materinya, «مادة (قدر)», tanpa juz/halaman; buktinya tetap `<<sid|juz|hal>>`.
- Menunjuk halaman lain di bahts ini: tulis `{A:kunci}` di matan tempat yang ditunjuk, lalu `[^انظر: ص{P:kunci} من هذا البحث.]`; nomornya diisi `rakit`.
- Cara menukil. Dasarnya أبو سليمان، كتابة البحث العلمي (ص73، 112-115، 121-123، 173-174): kitab itu tidak mengurutkan caranya; pilihannya menurut «الهدف، الأهمية، أهمية القائل، المناسبة» (ص112), dan kutipan «بالحجم المعقول، في المكان المناسب» (ص123). Urutan di bawah = aturan repo, cara yang lebih atas dipakai lebih dulu:
  1. Bawaan: الجمع (ص115): ringkasan, ikhtisar, atau uraian digabung dengan kutipan nash di sela pembahasan (contoh kitab: nash jadi pembuka ringkasan atau uraian). Aturan repo: yang dikutip bertanda petik cukup lafaz kuncinya (hukum, syarat, ta'lil), sisanya ditulis dengan kalimat sendiri; potongannya tidak boleh mengubah makna atau maksud pengarang (ص113، ص174).
  2. Kutip utuh (ص112): ayat dan sunnah; ungkapan pengarang yang penting (contoh repo: definisi istilah, nash mazhab yang jadi pokok khilaf); ungkapan yang sudah jelas dan pas; makna yang rawan bergeser; kalimat yang dibantah.
  3. التلخيص (ص113-114): satu pembahasan atau gagasan yang makan banyak halaman, ditulis dengan gaya sendiri; yang dijaga gagasan pokoknya. Aturan repo: dosen minta dirangkum dari beberapa sumber juga masuk sini; sumbernya diurutkan dari pengarang yang lebih dulu wafat (ص73); syarat dan pengecualiannya (إلا، ما لم، بشرط…) tetap ikut.
  4. الاختصار (ص114): teks dipadatkan jadi sepertiga atau seperempatnya, dengan tetap memakai gaya, sudut pandang, dan umumnya kata-kata pengarang; yang dibuang hanya penjelasan dan rincian. Mengganti beberapa kata saja bukan إعادة الصياغة dan tidak membuatnya jadi rumusan penulis (ص113). Aturan repo: kalimat seperti itu dijadikan الاختصار sungguhan (dipadatkan), atau dikutip bertanda petik.
  5. إعادة الصياغة (ص113): teks aslinya lemah ungkapannya, ruwet, atau kurang lengkap gagasannya (contoh repo: matan yang padat). Baca bagiannya, tutup kitabnya, lalu tulis dengan kalimat sendiri. Bahts tingkat «البكالوريوس» pada dasarnya mengumpulkan bahan lalu «صياغتها في أسلوبه الخاص» (ص31); aturan repo: بحث صفي termasuk di sini, dan di bahts seperti itu kalimat sendiri adalah tubuh pembahasan (lewat cara 1, 3, dan 5), bukan pengecualian.
  6. الشرح والتحليل (ص114-115): analisis penulis atas nash, dipisah jelas dari teks yang dikutip (ص173).
  7. الخطوط العريضة (ص115): mengenalkan isi satu kitab, risalah, atau nash tanpa rinciannya.
  Semua nukilan gagasan tanpa lafaz (cara 3-6, dan bagian ringkasan cara 1 dan 7) dirujuk dengan «انظر:» atau «راجع:» (ص114، ص173). التلخيص dan الاختصار dicocokkan lagi ke teks aslinya (ص114); aturan repo: إعادة الصياغة juga. Aturan repo: dosen minta "parafrase semua" → yang di nomor 2 tetap dikutip utuh (paling tidak ayat, hadits, definisi, dan kalimat yang dibantah), lalu sebut di laporan akhir.
  Tanda petik dan «انظر:»: nash yang dinukil utuh atau sebagian wajib di antara tanda petik supaya penulis tidak dituduh mencuri (ص113), dan «انظر»/«راجع» «تشير هذه الكلمة إلى تصرف الكاتب في النقل» (ص114). الاختصار boleh memakai kata pengarang (ص114); aturan repo: deret 8 kata atau lebih yang sama persis dengan kitab diberi tanda petik atau ditulis ulang, kecuali الاختصار yang disebut di laporan akhir. Aturan repo: bukti nukilan makna `<<sid|juz|hal|potongan>>` memakai potongan yang memuat inti gagasan yang dirujuk (hukumnya, syaratnya, ta'lilnya), bukan sembarang kata di halaman itu. Pendapat penulis ditulis tak langsung («والرأي»، «والراجح»), tanpa «أقول»، «قلت»، «قلنا»، «أرجح»، «نرجح» (ص193).
  Panjang kutipan: Abu Sulaiman memisah kutipan lebih dari empat baris jadi paragraf sendiri (ص219); pedoman risalah Jāmiʿat al-Imām (دليل إعداد وكتابة الرسائل العلمية، 2022، ص46) memisah kutipan lebih dari 60 kata dan memindah yang lebih dari 200 kata ke lampiran. Mesin belum punya tanda kutipan blok (`#T` = kotak matan merah, bukan penggantinya). Aturan repo: kutipan bertanda petik di luar nomor 2 paling panjang ±60 kata; yang lebih panjang dijadikan التلخيص atau الاختصار, dengan lafaz kuncinya saja yang tetap dikutip.
- Nukilan lafaz di antara tanda kutip (`cek` juga mengecek kurung «قال ﷺ: (…)» / «{H:…}(…)» dan kutipan pendek yang diantar «قال …:» seperti kutipan biasa); nukilan makna diawali `انظر:`. Penisbatan lewat perantara harus disebut perantaranya.
- الدراسات السابقة (kalau dosen minta): `#S` di المقدمة berjudul «الدراسات السابقة». Dasarnya أبو سليمان، كتابة البحث العلمي (ص60): penelitian lama dibaca «دراسة نقدية فاحصة» lalu ditulis «قائمة وصفية لها، وتقويمًا لمحتواها الموضوعي في اختصار». Tiap penelitian satu paragraf, urut dari yang terlama:
  1. Data: judul, peneliti, jenis (بحث محكم، رسالة ماجستير/دكتوراه), jurnal + jilid/nomor atau kampus, tahun. Data cetak lengkap (jilid, nomor, halaman) juga di المصادر والمراجع.
  2. Isinya: bahasan pokok dan temuan utamanya, satu-dua kalimat.
  3. «وجه الاتفاق:» dan «وجه الاختلاف:» dengan bahts ini.
  4. «التقويم:» penilaian singkat: kekuatannya, kekurangannya atau yang belum dibahasnya, dan yang diambil atau ditolak bahts ini darinya.
  Sesudah semua penelitian: «الإضافة العلمية» bahts ini. Panjangnya mengikuti jenis tugas. بحث صفي (`@jenis` «بحث صفي…», atau tugas kelas tanpa `@jenis`) → ringkas, ±satu halaman: boleh dibuka satu paragraf kitab turats bab itu sebagai مصادر (bukan penelitian, buktinya dari kitab yang menyebutnya), lalu 2-4 penelitian, masing-masing 2-3 baris (data, isinya satu frasa, tiap label satu frasa). رسالة/بحث تكميلي → lengkap seperti nomor 1-4. Diminta lebih ringkas dari itu (mis. tanpa label atau tanpa penilaian) → label dan «التقويم:» tetap ditulis, cukup satu frasa; sebut di laporan akhir. Isinya dari PDF penelitian yang benar-benar dibaca (`dirasat-pdf`, atau unduh dari situs jurnalnya), dirujuk `<<luar|berkas.pdf|hal>>`. Ringkasan saja tidak cukup; hanya kalau PDF-nya memang tidak bisa didapat: tulis «اطلعت على ملخصه» di catatan kakinya dan sebut di laporan akhir. Satu penelitian satu paragraf; labelnya ditulis persis dengan titik dua. `cek` memberi satu perhatian per penelitian yang tidak ber-PDF, tanpa salah satu label nomor 3-4, atau tidak urut tahun terbitnya (tahun terakhir sebelum catatan kaki pertama). `dirasat` mencari menurut kata dan menurut makna: kalau kata kunci pendek tidak ketemu, tulis masalahnya sebagai kalimat. Pencarian makna selalu memberi hasil, juga untuk kata yang tidak ada di penelitian mana pun: PERINGATAN «hanya MIRIP MAKNANYA» = menurut kata tidak ada yang cocok, jadi hasilnya bisa sama sekali tidak relevan; baca judul dan ringkasannya dulu. PDF-nya: `dirasat-pdf <W…> <folder>` (butuh kunci OpenAlex), lalu baca berkasnya. Kutipan dari isi PDF penelitian yang ada di folder bahts diberi `<<luar|berkas.pdf|hal>>` (hal = urutan halaman di berkas PDF, mulai 1; nomor tercetak jurnal tetap ditulis di catatan kakinya): `cek` hanya MENUNJUK halamannya, tidak pernah meloloskan. GAGAL «ada di halaman …» = betulkan hal-nya; perhatian «ditemukan di halaman …» = buka halaman itu dan cocokkan sendiri lafaz, angka, dan urutan katanya (teks PDF tidak dibaca persis); perhatian «tidak ada di teks PDF» = mungkin karangan atau lafaznya beda, bukan cuma PDF rusak/scan. Kutipan bertanda petik dari sumber di luar Shamela yang tidak punya PDF di folder (judul penelitian, jurnal yang tidak diunduh) diberi `<<luar>>`; `cek` tidak bisa membuktikannya, jadi lafaz dan halamannya dicocokkan sendiri ke sumbernya.
- Dilarang mengarang: nomor halaman, lafaz, penisbatan pendapat, dan derajat hadits harus terbaca di kitab lokal. Yang tidak bisa dibuktikan → jangan ditulis, atau laporkan sebagai «belum dicek».

## Yang perlu diketahui

- Bentuk halaman dan huruf dikunci mesin menurut pedoman Jāmiʿat al-Imām («القواعد المنظمة لتسجيل الرسالة العلمية وكتابتها وطباعتها وتقديمها»، 1442هـ). Dosen minta lain → beri tahu pemakai: profil baru di `mesin/format.json` adalah perubahan mesin (bagian «Untuk yang mengubah mesin»), bukan pekerjaan bahts. Di folder pemakai jangan mengubah berkas `mesin/`: `git status` jadi tidak kosong, lalu pembaruan mesin berhenti (Sebelum tiap bahts, langkah 2). Jangan ubah `imam`. Yang berbeda hanya nomor catatan kaki atau spasi matan → `@catatan_kaki`/`@spasi` (di atas), bukan profil baru. Bahts baru memakai `imam_ayat16` (lewat `mesin/naskah_baru.txt`): sama dengan `imam`, ayat 16 supaya tidak tampak lebih besar daripada matan; naskah tanpa `@format` tetap `imam`.
- Sampul bawaan = `mesin/sampul_qism.docx`; `@sampul: mahad` = `mesin/sampul.doc`, sampul معهد العلوم الإسلامية والعربية في جاكرتا (teks penandanya diganti `rakit.ps1`; huruf judul dibaca dari paragraf «عنوان البحث» di templat). Pembimbing tercetak hanya kalau `@musyrif` diisi; `@jabatan` kosong = baris jabatan tidak tercetak.
- PERINGATAN sesudah `rakit` (PDF tetap terbit) → bereskan sebelum lapor: titik-titik isian di sampul = isi atau hapus di naskah atau di Word `@templat`; sampul tidak memuat `@judul` = samakan judul sampul templat dengan `@judul` (atau `@judul` dengan judul dari dosen); nomor halaman 0123/bukan 0123 = rakit lagi, masih begitu → sebut di laporan akhir; baris terakhir matan berakhir «:» = buka halaman itu: pengantar yang terpisah dari isinya dibereskan lewat naskah (mis. paragraf pengantar dipendekkan), bukan lewat .docx.
- `rakit` butuh Windows + Microsoft Word. `rakit` satu-satu (memakai Word yang sama); yang terlanjur dijalankan bersamaan antre sendiri sampai 30 menit, jadi jalankan di latar, bukan dengan batas waktu alat yang lebih pendek. Pesan antre menyebut rakit yang sedang jalan (folder, proses, jam mulai). Jangan mematikan Word, PowerShell, atau Python rakit, dan jangan menghapus atau memindahkan folder `.rakit-*`: rakit yang dimatikan gagal tanpa hasil, dan sisanya (Word, `.rakit-*`) dibereskan sendiri oleh `rakit` berikutnya. Folder `.rakit-*` bukan tanda rakit sedang jalan; yang benar `tahap <folder>` (`RAKIT=JALAN` beserta folder, proses, dan jam mulainya). `rakit` menyebut «Folder .rakit-… dibiarkan» (tanpa penanda bahan sementara; mis. berisi `JANGAN_DIHAPUS.txt` = hasil baru yang belum terpasang, atau disimpan versi lama) → lapor ke pemakai, jangan dihapus sendiri.
- Teks kitab = ketikan Shamela, jadi bisa salah ketik. Bacaan yang meragukan: `ambil` edisi lain kitab yang sama lalu bandingkan; kalau masih ragu, cocokkan ke scan cetakan: `scan <id> <juz> <hal>` memberi alamat PDF cetakan halaman itu di turath.io (penunjuk jalan; tidak semua kitab punya scan), atau cari di archive.org.
- Yang dibaca dan dikumpulkan = PDF. `.docx` hanya untuk Word (di Google Docs tampilannya pasti beda). Perubahan isi selalu lewat `naskah.txt`, bukan lewat .docx.

## Untuk yang mengubah mesin

- Repo ini publik: nama orang, nomor mahasiswa, dan naskah siapa pun jangan masuk berkas yang dilacak git.
- Yang ada di `main` langsung dilihat semua orang. Perubahan dikerjakan di cabang lain (mis. `kerja`), dicoba dulu lewat pintu pemakai (`periksa`, `cek contoh`, `rakit contoh`), baru digabung ke `main` sebagai satu commit (`git merge --squash`).
